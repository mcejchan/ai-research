# Recording acceptance verification as a durable final note

When a monitor reports a missing final note after an implementation task, first use the authoritative plan and preserved task artifacts to identify the exact gap. Keep the repair scoped to the missing deliverable rather than repeating accepted implementation work.

For a verification-note requirement, list changed files separately from files only run by tests, link the existing genuine RED/GREEN proof, and record commands with observed outcomes. Clearly label results as historical when the follow-up is based on preserved session evidence and no commands were rerun. A checkpoint is useful for progress tracking but does not replace the required final note.
