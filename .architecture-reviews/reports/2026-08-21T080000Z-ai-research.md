## Verified findings

### 1. Pipeline documentation is a stale second authority for the executable runtime contract

**Problem**

`youtube-transcript-pipeline/README.md` copies mutable runtime facts rather than documenting a stable interface or deriving them from the runtime. Those copies now describe a materially different provider/auth/model setup and stale test state.

**Evidence**

- The README calls `OPENAI_API_KEY` required, describes direct OpenAI API credits/key troubleshooting, and says analysis uses `GPT-4o-mini`.
- `src/llm_client.py` instead defaults `OPENAI_BASE_URL` to `http://127.0.0.1:18800/v1/copilot`, defaults the API key to the local placeholder `copilot-bridge`, and defaults `LLM_MODEL` to `gpt-4o`.
- Runtime routing changed in April commits (`8ce9a80`, `b423276`, `f855416`, `a7ecff9`), while the README did not follow those changes. Its August edit updated only analysis artifact semantics.
- The README still claims `100% (37/37 tests pass)`. The current authoritative run collected 42 Python tests; all passed, but the claim is already numerically stale and coverage is not asserted as 100% by the gate.
- Fresh verification: root `make test` passed all Node suites and `42 passed in 23.08s` for pytest.

**Impact**

Operators are told to provision the wrong authority, diagnose failures against the wrong provider boundary, and trust a frozen test/coverage snapshot. Every provider/model/test change now requires synchronized prose edits with no drift guard. This adds cognitive load without adding a useful boundary.

**Recommendation**

Make source/config plus tests the sole authority for mutable runtime facts. Reduce the README to stable setup and interface guidance:

1. Document the supported environment variables and precedence without declaring copied defaults where avoidable; point to the owning source/config for defaults.
2. Describe the local bridge as the current default route and direct OpenAI as an explicit override, if both are intentionally supported.
3. Remove static pass-count and coverage claims; keep only the command (`make test`) and what scope it covers.
4. Add one focused documentation/runtime contract test only for facts that must remain user-visible. Do not create a generated metadata framework for this small repository.

## Self-critique

Documentation and code are legitimately separate artifacts: users need an operational explanation and should not have to read Python. The problem is therefore not “documentation exists,” but that it asserts volatile defaults, provider identity and test snapshots that have already diverged. The recommendation preserves the user boundary while shrinking copied facts. A broad schema generator would add more machinery than it removes; a small stable README plus, at most, a focused contract assertion has the better complexity tradeoff.

The bridge default may be intentionally local to Michal's environment while direct OpenAI instructions serve external users. If that portability is desired, it must be stated as two explicit modes with precedence—not presented as one required direct-provider contract while code silently chooses another.
